# Refactor Roadmap

Этот документ фиксирует безопасную стратегию рефакторинга без поломки рабочего сценария.

## Цель

Сделать проект более похожим на production-ready MVP:

- с единой логикой внутри пакета `pirate_monitor`;
- с воспроизводимой проверкой качества;
- с понятной структурой для GitHub и собеседований.

## Что уже сделано

1. Сетевой и статусный слой канонизированы в пакете:
   - `pirate_monitor.http`
   - `pirate_monitor.status`
2. Аналитический слой перенесён в пакет:
   - `pirate_monitor.analytics`
3. Основные orchestration-модули, storage и source adapters перенесены в пакет.
4. Добавлены:
   - `ruff`-конфигурация в `pyproject.toml`
   - GitHub Actions workflow для тестов

## Что переносим дальше

Следующие кандидаты для безопасного переноса:

1. дальнейшая нормализация структуры подпакетов;
2. вынос GUI/demo-слоёв в отдельные директории;
3. поэтапная зачистка старых generated артефактов и dev-only конфигов.

## Правила переноса

Чтобы не сломать проект, каждый перенос проходит по одному и тому же шаблону:

1. Создаём канонический модуль внутри пакета `pirate_monitor`.
2. Копируем рабочую логику без изменения поведения.
3. Обновляем импорты и тесты.
4. Проверяем проект тестами и ключевыми CLI-командами.

## Чего не делаем

- не меняем доменную логику ради “красоты”;
- не переписываем всё за один заход;
- не добавляем избыточную инфраструктуру;
- не тащим AI/agent-слой в ядро мониторинга.

## Критерий успеха

Рефакторинг считается успешным, если одновременно выполняются три условия:

1. проект запускается теми же командами, что и раньше;
2. существующие тесты проходят;
3. структура кода становится понятнее и легче для дальнейшего развития.
